OVK · Red-Team Panel

Know how it lands before you publish it.

A synthetic red-team panel that stress-tests draft public communications against weighted audience segments, skeptics, and hostile voices — and now runs for real: a Rust backend wired to the OVK panel engine over an immutable message bus, with a server-rendered HTMX interface on top.

LIVE  working end-to-end today  ·  NEXT  committed near-term  ·  LATER  production build-out

How it works

Everything rides the rapids — OVK's append-only, immutable flow queue. Messages are appended once and never modified, deleted, or consumed; every reader keeps its own durable cursor. That one property buys auditability for free: every number on every screen can be replayed from source.

Your screenverdict, favorability, strata — self-updating

The OVK engine fans the draft out to a demographically weighted panel of in-character personas, scores each reaction, and aggregates by stratum weight — a segment's share of the population, not its share of the panel — into a favorability prediction with per-archetype and per-locality breakdowns and a plain verdict: LIKELY WINS · MIXED · LIKELY FLOPS.

This project adds the product layer OVK deliberately doesn't have, in its own enrichment store: persona display metadata, the locked-voice redaction (a hostile persona's score counts, its reaction text is never shown), and per-run operator notes. Queue entries are referenced by ordinal, never copied-and-mutated.

The architectural bet: zero changes to OVK. The backend is just another producer/consumer on the bus — the integration pattern OVK's design explicitly blesses (non-destructive reads; N readers cost the same as one). Engine and product can evolve independently forever, because the only contract between them is the message types on the queue.

What's live today LIVE

  • End-to-end loop with real LLM personas, verified: submit a draft → 20-persona fan-out → replies and prediction stream back → verdict on screen. "model" is the default engine, routed through OVK's llm.sh seam; if the model box is unreachable the run degrades to mock with an honest label — never silently.
  • Resident panel listener.Answers any content:query on the bus — from this UI or any other producer. Skips queries already answered elsewhere, fast-forwards past history, and can't be wedged by unknown message types.
  • Red-team persona cast.OVK's marketing archetypes mapped to red-team roles — investigative journalist, regulator, watchdog, meme amplifier — with the hostile amplifier locked by default: its score counts, its text is never shown.
  • Calibration loop, closed in the UI.Record a run's real outcome (OVK's exact outcome:<item> format, appended to the rapids); the UI joins predicted vs actual per run and tracks the panel's mean signed error.
  • Bilingual EN/ET server-rendered UI.One click toggles; verdicts, roles, and every label localize. Matches the static demo before Estonian prospect conversations.
  • Native Rust client for the flow daemon's socket protocol.Protocol verified command-by-command against a live daemon; no OVK code linked.
  • Crash-safe consumer with full replay.Commit-after-ingest, idempotent ingestion — and if the local DB is ever wiped, the entire UI state rebuilds from the queue. Auditability demonstrated, not just claimed.
  • Enrichment store + HTMX UI.SQLite keyed by queue ordinals; lock-a-voice redaction, operator notes, per-run engine badge. Self-polling views, vendored htmx, no build step. The static bilingual sales demo remains untouched.

Why this is defensible

ClaimWhy it holds
Not just one AI prompt Weighted persona modeling with population strata, plus a calibration loop that joins every prediction to its real outcome and subtracts measured bias from the next one.
Auditable by construction The bus is append-only and immutable. Any prediction on any screen can be replayed entry-by-entry from the queue that produced it.
Honest by policy Predictions are labeled directional-only until real calibration cycles accrue. Statistical defensibility is earned empirically, never asserted from panel size.
Safe by default Hostile-amplification output is locked: its score informs the verdict, its text is never displayed or copyable.
What we won't tell you: that this predicts outcomes today. It doesn't — no real calibration data exists yet, and the UI says so on the tin. The pitch is the loop, not a fake accuracy number.
