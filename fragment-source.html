    Engineering handoff notes (English only — internal, not part of the pitch)
    
    
      
    Live modeSend the draft + each persona's system prompt to an LLM in parallel or sequential calls, one prompt per persona. Cap at 8–10 personas so live latency stays demoable in front of a prospect.
    
      
    Hard constraintThe hostile-amplification persona's reaction text must never be rendered as copyable/exportable UI content in a real build — score and flag reason only, same as this mockup's locked card.
    
      
    Score methodCanned cases use an unweighted mean of persona risk (0–100 scale, risk = (favorability+100)/2). The live-edit path uses a separate keyword-trigger estimator (baseline + per-trigger deltas). Both are placeholders — production should replace the estimator with the real LLM pass.
    
      
    Before / after caseOriginal and Revised drafts are two independently authored examples, not the tool rewriting text for you. The product flags risk, it doesn't generate copy — keep that distinction explicit in the pitch.
    
      
    Two scenariosTallinn school-network/language-transition and Tallinn diagnostics-turnaround (healthcare) are both fully built, bilingual (EN/ET), with independent draft/spans/persona-value/trigger data. Adding a third scenario means adding one more entry to the SCENARIOS object — the render pipeline is scenario-agnostic.
    
      
    i18n scopeEverything audience-facing is bilingual (EN/ET) via the STRINGS dict and per-field {en,et} objects. The JSON data-contract panels and this handoff section are deliberately left English-only — they're for engineering, not the pitch.
    
      
    Calibration tabEntirely mocked. Do not wire it to any real metric until actual predicted/actual outcome pairs exist for real published drafts.
    
      
    ContentNever load real prospect draft text into the scenario picker without explicit permission. Both drafts are fictional: the education one is an invented city-government notice modeled on Tallinn's school network and the language-of-instruction transition, and the healthcare one ("BaltiLabor") is an invented lab operator with invented Tallinn collection points. Districts (Mustamäe, Lasnamäe, Nõmme, Põhja-Tallinn, Väike-Õismäe) are real places used as audience geography — no named school, clinic, official or real communication appears anywhere.
    
      
    Audience geographyPersonas are segmented by Tallinn district (Kesklinn/Kristiine, Nõmme, Mustamäe, Lasnamäe) rather than nationally. District ids are used as the persona keys throughout the data, so re-pointing the pilot at another city means swapping PERSONA_META_BASE plus the per-scenario baseline/values/deltas keys — nothing in the render pipeline is Tallinn-specific.
